## 一、SPA 与 MPA 的根本差异

传统多页应用（MPA）中，每个路由对应一个独立的 HTML 文件。用户跳转时，浏览器请求新的 HTML 文件，旧页面的全部资源被销毁，新页面从零开始加载和渲染。每次跳转都伴随白屏等待，页面状态随之丢失。

单页应用（SPA）则只包含一个 HTML 文件。首次加载时，框架运行时、路由配置和公共资源一次性下载完毕。后续的路由跳转不再请求新的 HTML 文件，而是由前端路由在当前页面内切换组件。URL 发生变化，但浏览器不刷新页面，JavaScript 运行时持续存活。

## 二、Vue Router 如何实现前端路由

Vue 构建的 SPA 确拥有多个"页面"，但这些页面并非独立的 HTML 文件，而是注册在路由表中的组件。

```js
const routes = [
  { path: '/',      component: Home },
  { path: '/about', component: About },
  { path: '/user',  component: User }
]
```

浏览器提供了 History API，允许 JavaScript 修改 URL 而不触发页面刷新：

```js
history.pushState({}, '', '/about')
```

Vue Router 调用该 API 修改 URL，同时监听 URL 变化，将 `router-view` 中的组件替换为路由表对应的组件。浏览器地址栏显示新路径，用户感知到"页面跳转"，实际发生的是同一页面内的组件切换。

## 三、为什么 SPA 是 Vue 的必要条件

对于传统 MPA 而言，SPA 是一种体验优化策略，用首次加载的额外开销换取后续跳转的流畅体验。但对于 Vue 而言，SPA 并非可选项，而是框架运行的必要条件。

Vue 在内存中维护着组件树和响应式数据。Pinia 管理的全局状态、组件内部的生命周期、跨组件共享的数据，全部依赖一个持续存活的 JavaScript 运行时。MPA 每次跳转都销毁当前页面，Vue 实例被回收，Pinia store 归零，组件状态消失殆尽。跨页面的状态管理在这种模型下无从谈起。

换言之，Vue 的响应式系统、状态管理、组件通信机制能正常工作的前提，是页面不刷新、运行时不销毁。SPA 不是 Vue 主动选择的优化策略，而是 Vue 运行机制的结构性要求。Vue Router、Pinia 等生态组件的 设计均建立在这一前提之上。

## 四、SPA 的首次加载问题与应对

SPA 的主要代价在于首次加载。框架运行时代码、路由配置、所有页面的组件代码需要在首次访问时下载，初始加载时间显著长于 MPA。业界对此的应对方案是路由懒加载：

```js
// 静态导入：所有组件打包在一起，首次加载全部下载
import Home from './Home.vue'

// 动态导入：组件单独打包，访问到对应路由时才加载
const Home = () => import('./Home.vue')
```

采用动态导入后，每个路由被分割为独立的代码块。首次加载只下载首页所需的代码，其他页面在用户访问时按需获取。首次加载慢的问题由此大幅缓解。

## 五、渐进式框架与 SPA 的关系

Vue 被称为渐进式框架，开发者可以按需逐步引入功能。仅用核心库做视图渲染时，一个 `<script src="vue.js"></script>` 就能驱动一个简单页面，无需 Vite、Pinia 或 Vue Router。引入 Vue Router 后获得前端路由能力，引入 Pinia 后获得跨组件状态管理能力，引入 Vite 后获得完整的工程化构建支持。

这一渐进式体系的每一层扩展，都以 SPA 为运行基础。没有 SPA，Vue Router 的前端路由无法存活，Pinia 的状态管理无法跨页面共享。渐进式是功能层面的按需引入，SPA 则是这一切得以运转的底层前提。
